CORREZIONE DATI INIZIALI + FLASHBACK BUILD PRECEDENTI

PROBLEMA 1 — PERIODO VUOTO 2026-09
Il cloud contiene già dati finanziari con ultimo periodo 2025-12,
ma il browser poteva conservare 2026-09 in sessionStorage/localStorage.
La vecchia priorità era:
  periodo browser → periodo dati
quindi veniva aperta una schermata vuota.

ORA LA PRIORITÀ È:
  periodo cloud valido → ultimo periodo con dati → periodo browser valido → mese corrente

Un periodo salvato nel browser viene ignorato se non contiene realmente
né uno snapshot SPRING né un record finanziario.

PROBLEMA 2 — FLASHBACK DI VERSIONI PRECEDENTI
Il precedente service worker serviva JavaScript dalla cache e poi lo aggiornava
in background. Dopo un deploy poteva quindi partire per un istante il planner
della build precedente.

ORA:
- HTML: network-first
- JavaScript/CSS applicativi: NETWORK-FIRST
- cache: solo fallback se la rete non è disponibile
- loghi/immagini: restano cache-first per velocità
- tutte le vecchie cache vengono eliminate all'attivazione

BUILD CONSISTENCY
Da V11.8.3 in avanti, quando un nuovo service worker prende il controllo,
la pagina fa automaticamente UN refresh. Questo impedisce di mescolare
access/planner di due build diverse nella stessa sessione.
